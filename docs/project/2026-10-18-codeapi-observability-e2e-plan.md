### Approved wrapped-execution extension

The existing native-wrapper gate is reached. Extend only `api/src/tool-call-pipe-broker.ts` and `api/src/tool-call-pipe-bridge.c` alongside the already approved runner files. The chain is runner API → Node broker → native pipe relay → NsJail → guest. Orderly caller cancellation and tool-channel abandonment must stop work through that chain and reap each child before workspace cleanup/identity release. This adds no dependency, endpoint, privilege, capacity or image/deployment effect. The user approved these two additional production paths and their source verification.

**Startup ownership.** Keep the native `--broker` exec shape. The Node broker installs TERM/INT handlers before spawning any relay. Before those handlers exist, default signal termination can only stop the childless startup; imports must remain free of child-spawn effects. After installation, shutdown is an idempotent flag that is checked before spawn and applied to the child immediately after assignment, including synchronous spawn failure. A pending signal is handled after synchronous child registration. In native `--job-pipes`, block TERM/INT before fork and install signal-intent handlers before creating a child. Parent registration precedes restoring its mask; forward any recorded intent to the exact owned PID. The exec child resets inherited handlers, restores its original mask and retains existing parent-death checks before exec. A child killed before exec has no guest descendants. Qualification must verify that the pinned NsJail installs its own termination handling before creating guest children; otherwise stop for a revised design. No new readiness channel is introduced.

**Shutdown and EOF.** Runner cancellation sends TERM only to the owned direct NsJail or broker, never hard-kills the whole chain. Broker shutdown stops new tool requests, destroys outstanding upstream requests and closes tool pipes, then forwards TERM to the relay and awaits its exit/stdio settlement. Relay TERM/INT, either broker-facing endpoint closure/error, a truncated frame propagated as channel failure, or loss of its guest-facing capability reader initiates the same one-time child termination path. A guest request-writer EOF alone is not abandonment: programs may never use the tool capability, and the relay keeps the upstream writer until child exit. Interrupted polls/waits resume. Relay closes/discards control buffers during teardown so backpressure cannot keep it in a transfer loop, while the API continues draining stdout/stderr until the chain settles. Clean upstream EOF and malformed/truncated EOF both terminate the owned invocation, but are not reported as successful tool completion. Concurrent signals and channel-close events do not signal another PID or acknowledge twice.

**Unresolved shutdown.** After a five-second graceful observation window the runner records a fixed, values-free termination-stalled diagnostic but keeps awaiting the same process and streams. The disconnected HTTP caller already observes transport abort. The route/job retains its active execution, workspace and identity; no result/upload, cleanup, UID reuse or hard-kill escalation follows from watchdog expiry. A later real child exit settles that original owner and permits normal cleanup. If it never exits, the slot remains unavailable pending operator recovery through existing authority. This deliberately trades capacity for preventing unsafe identity reuse. The source acceptance test must prove no release at watchdog expiry and eventual settlement on actual exit. This is runtime behavior, separate from a failed development check.

**Crash boundary.** Preserve existing `PR_SET_PDEATHSIG=SIGKILL` as crash protection. Unexpected owner death bypasses orderly shutdown and may leave unreaped processes; this extension makes no crash-time reaping guarantee. Source-owned tests verify the inherited parent-death behavior and absence of later successful work, separately from orderly-cancellation tests. Changing crash semantics would require another explicit design/approval.
