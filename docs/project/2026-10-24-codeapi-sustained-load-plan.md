### Workload and timing

Prepare three deterministic workload templates once before timed admission: the existing million-step Python SHA-256 chain, 32-MiB Python memory-integrity program and 32-MiB Node memory-integrity program. Separate a fixed workload seed from each request nonce. Extend the existing resource-workload helper with an optional seed defaulting to the nonce, preserving existing modes. Compute each template digest once from its fixed seed. Bind an inexpensive unique echoed nonce `runId:plateau:slot:caller:position` into each generated program and verify it exactly alongside the fixed digest. This detects swapped responses without expensive per-request oracle work. Preparation happens outside plateau timing and cannot silently extend the invocation deadline. Do not compute expensive per-request oracles on the timed dispatch path.

The operator imports `runQualification` with fresh in-memory 240-second JWT supplier functions for each caller; it does not use constant CLI bearer values for this run, lengthen token lifetimes or save token files. The generic CLI still requires credentials valid for its full invocation and reports an authentication failure honestly if they expire. Run the existing full direct contract under caller A with caller B performing its ownership-denial check. Wait the existing full execution-rate window after the contract. Preflight refuses load unless the deployed ordinary per-principal execution window has an execution window of exactly 30000 ms and permits at least twelve requests in that window and the client can complete all fixed intervals within its admission bound. Do not change or evade those limits. Both principals are fixed for the complete invocation, not rotated. Baseline trust remains the already-approved issuer/profile.

Each plateau lasts at least 480000 ms and has 48 slots spaced 10000 ms apart. Plateau one offers one request per slot (48 total), alternating caller A/B. Plateau two offers two requests per slot (96 total), one per caller. Plateau four offers four requests per slot (192 total), two per caller. The order of caller submission alternates by slot to reduce systematic first-submitter bias. Before reserving any wave, require current global in flight plus wave demand to be at most four and each caller in flight plus its wave demand to be at most two. Globally cap in flight at four and per caller at two. The offered plateau level is a burst ceiling, not a claim of continuously occupied execution slots.

Choose workload kinds in a fixed cyclic mix `[cpu, memory, node_memory, cpu]` across the offered calls, balanced between callers within each plateau. For one-request slots, alternate callers and select kind at index `floor(slot / 2) % 4`, forming balanced eight-slot blocks. For two-request slots, each caller receives kind at index `slot % 4`. For four-request slots, each caller receives kinds at indices `(2 * slot) % 4` and `(2 * slot + 1) % 4`. Alternate caller submission order each slot. Each caller receives CPU/memory/Node-memory counts 12/6/6, 24/12/12 and 48/24/24 across the three plateaus. Receipt samples contain plateau, slot, caller label, kind, language, guest CPU/wall time and client elapsed time. Validate exact nonce/digest/byte count, successful guest status, empty stderr and no unexpected generated artifacts.

Schedule from a monotonic clock. A slot more than 1000 ms late or still blocked by unsettled prior requests is incomplete coverage: stop admission, settle admitted work, preserve the cause and run cleanup. Do not catch up, bunch slots, retry calls or replace missing coverage with defaults. This is a finite offered-load coverage criterion, not a uniform latency SLO: higher offered waves can exhaust the shared in-flight budget sooner. Report the effective overlap and blocking condition per plateau. Every offered request must settle before that plateau's absolute end; the final slot has ten seconds of runway. A longer request can be an honest workload/transport limitation rather than proof of a service outage. The finite timing contract remains explicit.

Wait through every complete plateau, including its final observation-only interval. Require a new guard observation timestamped at or after each plateau's end within ten seconds, then start the next plateau. Failed/missing interval proof holds dependent plateaus. Before any load admission, require actual elapsed time plus the 31000-ms rate wait plus three times 490000 ms to fit the 1620000-ms ordinary-admission bound. The clock for invocation and scheduler deadlines is monotonic; wall anchors are used only to match the same-host observer timestamps.

Attach a rejection handler immediately to every dispatched request. Any failure stops new admission; retain all outstanding promises and await their settlement before cleanup begins. Failure receipts carry plateau, slot, caller and workload kind. Cleanup cannot race still-admitted work.
