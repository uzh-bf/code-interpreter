## Preservation decisions

- Keep the fork's KVM-first sandbox defaults, sandbox-runner namespace and
  security hardening, external replica/chart ownership, package lifecycle,
  restricted metrics peers and other existing chart values.
- Keep issuer-keyed JWT trust, values-free operational logs, nonfatal telemetry,
  missing artifact-bucket readiness, refusal-only bounded retry, caller
  cancellation and guest cleanup ownership, and default-disabled synthetic
  lifecycle observation.
- Combine upstream file-server store pairing with the fork's missing-bucket
  readiness. A store mismatch or failed dependency probe must fail readiness;
  neither behavior may silently override the other.
- Keep graceful sandbox drain opt-in (`gracefulDrain.enabled=false`) and retain
  the current sandbox-runner termination behavior by default. Its new chart
  validation and lifecycle hooks are inert unless enabled.
- Keep detached commands gated by more than one workspace lease slot. The fork
  compose and managed deployment defaults remain at one slot, so the effective
  default stays serialized. Preserve the upstream protocol and its guards when
  an operator explicitly raises the slot count.
- Preserve the fork's never-publish policy. The upstream package workflow's
  publish job is restricted to the upstream repository; this fork creates no
  `code-v*` tag, npm publication, GitHub release or release credential.
- Retain the fork's seven-image exact-SHA publication workflow and disabled
  repository release job. No image or deployment change belongs to this PR.

The 17 fork-touched paths also changed by upstream are accounted for during the
merge. Every other upstream path is adopted as release history. A conflict is
resolved at the owning layer: upstream security/protocol behavior plus the
fork behavior named by `docs/fork/patches.md`. A clean textual merge is not
semantic proof.
